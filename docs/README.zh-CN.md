# Session Guardian 中文指南

Session Guardian 用于防止 Codex 长任务持续携带过大的会话上下文，导致每次请求上传量增大、响应变慢或出现多条大流量连接。

## 原理

Codex 在每次提交用户提示和回合结束时调用插件 Hook。插件使用 Codex 提供的 `transcript_path` 文件字节数衡量会话体积，不依赖不稳定的 JSONL 内部格式。

默认只有一个 64 MiB 阈值。当任务达到阈值后，下一条用户消息会在提交后、Codex 开始处理前被本地阻断。插件保存第一条被阻断的业务消息，并提示用户回复 `是`。用户确认后，Codex 才执行一次携带完整上下文的交接请求。

会话日志大小是唯一的自动检测信号。插件不读取 Clash/Mihomo 连接，不采集代理流量、系统网络计数器或数据包；未安装任何代理软件也不影响使用。

用户回复 `是` 后（兼容 `继续交接`），才会发起唯一一次携带完整上下文的交接请求：

1. 当前 Codex 直接利用已加载的上下文生成结构化交接摘要，不再发起第二次摘要请求；
2. 通过 Codex App 的任务管理能力新建一个精简任务，写入目标、已完成项、决策、文件变更、验证结果和待办项；
3. 等待新任务创建成功并确认它已准备好，然后使用 `navigate_to_codex_page` 导航到该任务，确保界面回到刚创建的会话，而不是停在“新对话”页面；
4. 最后由当前任务归档自己。

任何一步失败都不会归档旧任务，Codex 会在当前回合中告知具体错误。归档是可恢复的，可以在 Codex 的已归档任务中找回。

被 64 MiB 阈值拦截的用户提示不会在旧任务中执行；用户确认交接后，它会在新任务中自动继续执行。

## 安装

```bash
codex plugin marketplace add Komorebi-Liao/codex-plugins --ref main
codex plugin add session-guardian@komorebi-codex-plugins
```

安装后重启 Codex 或新建任务。Codex 会要求审查并信任插件 Hook；在 CLI 中可使用 `/hooks` 查看。

## 使用

在 Codex 中可以说：

- “检查当前会话是否过长”
- “现在就交接到新任务”
- “Session Guardian 改为只提醒，不自动归档”
- “把交接阈值改为 48 MiB”
- “取消已排队的会话交接”

也可以显式调用 `$session-rollover`。

## 模式

- `auto`：达到阈值后在任务运行前阻断提示，用户确认后交接，默认。
- `warn`：只提醒，不新建或归档任务。
- `off`：关闭检测。

配置和运行状态保存在 Codex 分配给插件的私有数据目录，不会进入代码仓库。
